Cursor ထဲမှာ code ရေးတိုင်း သုံးတဲ့ AI က စကားပြောခန်း တစ်ခု ပြီးတိုင်း အကုန် မေ့သွားတတ်တယ်။ CursorMemo က မှတ်စုစာအုပ်တစ်အုပ်လို အလုပ်လုပ်တယ် — မင်း ဘာလုပ်ခဲ့လဲ၊ ဘာအဆင်ပြေလဲ၊ ဘာကျန်နေသေးလဲ ဆိုတာ တိတ်တိတ်လေး မှတ်ထားပေးတယ်။ နောက်တစ်ခါ project ဖွင့်တာနဲ့ AI က အဲ့ဒီမှတ်စုကို ကြိုဖတ်ထားပြီးသား ဖြစ်နေတယ်။

The AI you code with in Cursor forgets everything when a chat ends. CursorMemo works like a notebook — it quietly records what you did, what worked, and what's still open. The next time you open the project, the AI has already read that notebook. No more re-explaining from scratch.

အလိုအလျောက် မှတ်တယ်

Automatic notes

မင်း ဘာမှ နှိပ်စရာ မလိုဘူး။ အလုပ်လုပ်နေတိုင်း — ဘာလုပ်ခဲ့လဲ၊ ဘာ error တွေ့လဲ၊ ဘာဆုံးဖြတ်ခဲ့လဲ — မှတ်စုက သူ့ဘာသာ ရေးသွားတယ်။

You never press anything. As you work — what you did, what error you hit, what you decided — the notebook writes itself.

🤝

နောက် session က ဆက်ကောက်တယ်

Next session picks it up

Session တစ်ခု ပြီးတိုင်း မှတ်စုကို အကျဉ်းချုပ် ရေးထားပေးတယ်။ နောက် session စတာနဲ့ AI က အဲ့ဒါကို ကြိုဖတ်ထားပြီးသား ဖြစ်နေတယ်။

At the end of each session a summary is written down. The next session starts with the AI having already read it.

🗂️

Project တိုင်း သီးခြား မှတ်စု

A notebook per project

မှတ်စုတွေကို project တစ်ခုချင်းစီ အလိုက် folder လမ်းကြောင်းနဲ့ ခွဲသိမ်းတယ်။ Project အသစ် ဖွင့်တိုင်း မှတ်စု အသစ်က အလိုအလျောက် စတယ်။

Notes are kept separately per project, scoped by folder path. A new project automatically starts a fresh notebook.

🔑

API key မလိုဘူး

No API key needed

အခြေခံ ပုံစံက အင်တာနက်က AI ဝန်ဆောင်မှုကို မသုံးဘူး။ Key မရှိ၊ အကောင့် မရှိလည်း အပြည့်အဝ အလုပ်လုပ်တယ်။

The default setup uses no online AI service at all. No key, no account — it works fully offline after install.

🏠

Data က ကိုယ့်စက်ထဲပဲ

Your data stays home

မှတ်စုတွေ အကုန် မင်းရဲ့ ကွန်ပျူတာထဲမှာပဲ သိမ်းတယ်။ အပြင်က server ကို ဘာမှ မပို့ဘူး။ ကိုယ့် code အကြောင်း သူများ မသိဘူး။

Every note is stored on your own computer. Nothing is sent to an outside server — nobody learns about your code.

📖

စာအုပ်လို ပြန်ဖတ်လို့ရတယ်

Readable like a book

မှတ်စုတွေက ရိုးရိုး စာဖိုင်တွေ (markdown)။ ကိုယ်တိုင် ဖွင့်ဖတ်လို့ရတယ်၊ ပြင်လို့ရတယ်၊ ရှာလို့ရတယ်။ ပိတ်ထားတဲ့ ပုံစံ မဟုတ်ဘူး။

Notes are plain text files (markdown). Open them, read them, edit them, search them — nothing is locked away.

ဥပမာ admin လို့ ရိုက်ထည့်ရင် ရပြီ။ စနစ်က username ကို မစစ်ဘူး။

Type anything, for example admin. The system does not check the username.

2

Password — ကိုယ့်စက်ထဲက token ဖိုင်

Password — the token file on your machine

Password က ကိုယ့်စက်ထဲမှာ သိမ်းထားတဲ့ token ဖိုင်ထဲက စာသားပဲ။ Windows (PowerShell) မှာ ဒီ command နဲ့ ကြည့်ပြီး ကူးထည့်ပါ:

The password is the text inside a token file stored on your own machine. On Windows (PowerShell), view it with this command and paste it in:

Get-Content "$env:LOCALAPPDATA\ai-memory\auth-tokens\default"

WSL2 / Linux ဆိုရင်:

On WSL2 / Linux instead:

cat ~/.local/share/ai-memory/auth-tokens/default
3

Token ကို လျှို့ဝှက်ထား

Keep the token secret

အဲ့ဒီ token က ကိုယ့် မှတ်စုတွေရဲ့ သော့ချက်ပဲ။ ဘယ်သူ့ကိုမှ မပေးနဲ့၊ chat ထဲ၊ screenshot ထဲ မပါစေနဲ့။

That token is the key to your notes. Never share it with anyone, and keep it out of chats and screenshots.

တင်တာ အောင်မြင်လား စစ်နည်းHow to check it really works

တင်ပြီးရင် အဆင့် ၄ ဆင့်နဲ့ စစ်လို့ရတယ်။ နောက်ဆုံး အဆင့်က အရေးကြီးဆုံး စမ်းသပ်ချက်ပဲ။

After installing, verify with these four checks. The last one is the test that really matters.

1

Program ရှိလား စစ်

Check the program is installed

Terminal (PowerShell) မှာ ဒီ command တွေ run ပါ။ 3.1.1 လို့ ပေါ်ပြီး doctor က စစ်ဆေးချက် အဆင်ပြေတယ်လို့ ပြရင် engine အောင်မြင်ပြီ:

Run these in a terminal (PowerShell). If the version shows 3.1.1 and the doctor checks pass, the engine is in:

ai-memory --version; ai-memory doctor; ai-memory status
2

Server run နေလား စစ်

Check the server is running

Browser မှာ http://127.0.0.1:49374/web ဖွင့်လို့ sign in တောင်းတဲ့ မျက်နှာ ပေါ်လာရင် server အလုပ်လုပ်နေပြီ။ အပေါ်က နည်းအတိုင်း ဝင်လို့ရရင် အဲ့အပိုင်း အတည်ပြုပြီ။

Open http://127.0.0.1:49374/web in your browser. If the sign-in prompt appears, the server is running — and once you can sign in with the steps above, that part is confirmed.

3

Cursor နဲ့ ချိတ်မိလား စစ်

Check Cursor is wired up

Cursor ထဲမှာ Settings → MCP ကို ဖွင့်ပါ။ ai-memory ဆိုတဲ့ server တစ်ခု enabled ဖြစ်နေရမယ်။ မတွေ့ရင် ချိတ်ဆက်မှု မအောင်မြင်သေးဘူး — installer ကို ပြန် run ကြည့်ပါ။

In Cursor, open Settings → MCP. An ai-memory server must be listed and enabled. If it is missing, the wiring did not finish — run the installer again.

4

တကယ် မှတ်မိလား စမ်း — အရေးကြီးဆုံး

Test the memory itself — the one that matters

Project တစ်ခုမှာ chat ဖွင့်ပြီး AI ကို အချက်တစ်ခု ပြောထားပါ (ဥပမာ "ဒီ project မှာ PostgreSQL သုံးတယ်၊ မှတ်ထားပေး")။ ပြီးရင် chat ပိတ်ပြီး Dashboard မှာ အဲ့ဒီ project အောက် page အသစ် တိုးနေလား ကြည့်ပါ။ နောက်ဆုံး chat အသစ် ဖွင့်ပြီး ဘာမှ ပြန်မရှင်းပြဘဲ "What do you remember about this project?" လို့ မေးပါ — အရင် chat က အချက်တွေ ပြန်ဖြေနိုင်ရင် တကယ် အလုပ်ဖြစ်ပြီ။

In a project chat, tell the AI one fact (for example "this project uses PostgreSQL — remember that"). Close the chat and check the dashboard: a new page should appear under that project. Then open a fresh chat and, without explaining anything again, ask "What do you remember about this project?" — if it answers with facts from the earlier chat, the memory truly works.

ဘယ်လို နည်းစနစ်နဲ့ ဖန်တီးထားလဲ

How is it built?

CursorMemo က အပိုင်း ၂ ပိုင်း ပေါင်းစပ်ထားတာ — နောက်ကွယ်က အင်ဂျင် (ai-memory) နဲ့ အပေါ်က ထုပ်ပိုးမှု (CursorMemo)။ တစ်ခုချင်းစီ ဘယ်လို လုပ်ထားလဲ ရှင်းပြထားတယ်။

CursorMemo combines two parts — the engine behind it (ai-memory) and the packaging on top (CursorMemo). Here's how each one works.

အပိုင်း ၁ — အင်ဂျင်: ai-memoryPart 1 — The engine: ai-memory

Rust ဆိုတဲ့ programming language နဲ့ ရေးထားတဲ့ program တစ်ခုတည်း (binary တစ်ဖိုင်တည်း)။ Server သီးခြား, database သီးခြား တင်စရာ မလိုဘူး — အဲ့ဒီတစ်ဖိုင်တည်းက အကုန် လုပ်တယ်။

A single program (one binary file) written in the Rust programming language. No separate server or database to install — that one file does everything.

Cursor

မင်း code ရေးတဲ့ နေရာ။ အဖြစ်အပျက်တွေကို hooks က မှတ်တယ်။

Where you write code. Events are captured by hooks.

Over the MCP standard, the AI searches and reads the notebook. Hooks mark session start/end.

မှတ်စု server

The note server

ကိုယ့်စက်ထဲမှာပဲ run တယ် (127.0.0.1)။ မှတ်စုတွေ စုစည်း, သိမ်း, ပြန်ရှာပေးတယ်။

Runs only on your own machine (127.0.0.1). Collects, stores, and searches the notes.

အလုပ်လုပ်ပုံ အဆင့် ၄ ဆင့်The 4-step pipeline

1

မှတ်ယူတယ် (Capture)

Capture

Cursor ရဲ့ lifecycle hooks က session တစ်ခုလုံးရဲ့ အဖြစ်အပျက်တွေ — မင်း ဘာမေးလဲ၊ AI ဘာ tool သုံးလဲ၊ session ဘယ်တော့ စပြီး ဘယ်တော့ ပြီးလဲ — ကို တိတ်တိတ်လေး server ဆီ ပို့တယ်။

Cursor's lifecycle hooks quietly send the session's events — what you asked, what tools the AI used, when the session started and ended — to the server.

2

စစ်ပြီး သန့်တယ် (Sanitize)

Sanitize

မသိမ်းခင် အရင် စစ်တယ် — password, API key လို အရေးကြီးတဲ့ အရာတွေ ပါလာရင် ဖယ်ပြီးမှ သိမ်းတယ်။

Before anything is stored, it is checked — passwords, API keys, and other secrets are stripped out first.

3

စာမျက်နှာ အဖြစ် စုစည်းတယ် (Consolidate)

Consolidate

Session ပြီးတာနဲ့ အဖြစ်အပျက်တွေကို ဖတ်ရလွယ်တဲ့ markdown စာမျက်နှာတွေ အဖြစ် ပြောင်းတယ်။ ဒီစာဖိုင်တွေက မှတ်စုရဲ့ မူရင်း အရင်းအမြစ် — git နဲ့ version မှတ်တမ်း ထိန်းထားတယ်။ ရှာရမြန်အောင် SQLite database (FTS5 full-text search) နဲ့ အညွှန်း ထပ်လုပ်တယ်။

When a session ends, its events become readable markdown pages. Those files are the source of truth, versioned with git. A SQLite database (FTS5 full-text search) indexes them for fast lookup.

4

ပြန်ရှာပြီး လက်ဆင့်ကမ်းတယ် (Recall + Handoff)

Recall + Handoff

နောက် session စတာနဲ့ ရှေ့ session ရဲ့ အကျဉ်းချုပ်ကို AI ဆီ အလိုအလျောက် ပို့ပေးတယ်။ AI က လိုရင် မှတ်စုထဲမှာ full-text search နဲ့ အသေးစိတ် ထပ်ရှာလို့ရတယ်။ အခြေခံ ပုံစံမှာ ဒီအဆင့်အားလုံး AI API လုံးဝ မသုံးဘူး — key မလိုဘူး။

When the next session starts, the previous summary is handed to the AI automatically. If needed, the AI can dig deeper with full-text search. The default setup uses no AI API for any of this — no key needed.

အပိုင်း ၂ — ထုပ်ပိုးမှု: CursorMemoPart 2 — The packaging: CursorMemo

CursorMemo ကိုယ်တိုင်က code အသစ် မဟုတ်ဘူး။ သူများတွေ အလွယ်တကူ တင်သုံးနိုင်အောင် လုပ်ထားတဲ့ ထုပ်ပိုးမှုပဲ။

CursorMemo itself is not new code. It's the packaging that makes the engine easy for anyone to install and use.

📦

Installer scripts

Installer scripts

Windows အတွက် PowerShell script, Linux/macOS အတွက် Bash script။ အဲ့ဒီ script တွေက ai-memory ရဲ့ တရားဝင် installer ကို ခေါ်သုံးပြီး Cursor တစ်ခုတည်းနဲ့ပဲ ချိတ်ဖို့ setup --agent cursor ဆိုတဲ့ အမိန့်ကို run ပေးတယ်။

A PowerShell script for Windows and a Bash script for Linux/macOS. They call ai-memory's official installer, then run setup --agent cursor to wire Cursor only.

🌐

ဒီ website

This website

Static web page တစ်ဖိုင်တည်း (HTML + CSS + JavaScript)။ Framework မပါ, build လုပ်စရာ မလို။ Server ပေါ်မှာ nginx နဲ့ တင်ပြီး Let's Encrypt HTTPS လက်မှတ် သုံးထားတယ်။

A single static web page (HTML + CSS + JavaScript). No framework, no build step. Served by nginx with a Let's Encrypt HTTPS certificate.

🐙

GitHub + MIT license

GitHub + MIT license

Source code အကုန်ကို GitHub မှာ public တင်ထားတယ်။ ai-memory လည်း MIT, CursorMemo လည်း MIT — ဘယ်သူမဆို အခမဲ့ သုံး, ပြင်, ပြန်ဝေလို့ရတယ်။

All source code is public on GitHub. Both ai-memory and CursorMemo are MIT — anyone can use, modify, and share them for free.

🔍 အကျဉ်းချုပ် — Rust program တစ်ခုတည်းက မှတ်စု server အဖြစ် ကိုယ့်စက်ထဲမှာ run တယ်။ Cursor က MCP + hooks နဲ့ ချိတ်တယ်။ မှတ်စုက markdown စာဖိုင်တွေ + SQLite အညွှန်း။ CursorMemo ကတော့ အဲ့ဒါကို တစ်ချက် install နဲ့ မြန်မာ လမ်းညွှန် ပေါင်းထည့်ထားတဲ့ ထုပ်ပိုးမှု။🔍 In short — one Rust program runs as a note server on your own machine. Cursor connects over MCP + hooks. Notes live as markdown files plus a SQLite index. CursorMemo wraps all of it with a one-line install and this guide.

မေးလေ့ရှိသောမေးခွန်းများ

Frequently asked questions

လူတွေ အမေးများတဲ့ မေးခွန်းတွေကို စုပြီး ဖြေထားတယ်။

Answers to the questions people ask most.

API key လိုလား? ပိုက်ဆံ ကုန်လား?

Does it need an API key? Does it cost money?

မလိုဘူး၊ မကုန်ဘူး။ အခြေခံ ပုံစံက လုံးဝ အခမဲ့။ မှတ်စုကို အလိုအလျောက် ရေးပေးတဲ့ အလုပ်ကို ကိုယ့်စက်ထဲက program ကပဲ လုပ်တယ် — အပြင် AI ကို မခေါ်ဘူး။

No and no. The default setup is completely free. The note-writing is done by the program on your own machine — no outside AI is called.

မှတ်စုတွေ ဘယ်မှာ သိမ်းထားလဲ? သူများ မြင်နိုင်လား?

Where are the notes stored? Can others see them?

မင်းရဲ့ ကွန်ပျူတာထဲမှာပဲ သိမ်းတယ်။ အပြင်က server ကို ဘာမှ မပို့ဘူး။ Server ကလည်း မင်းရဲ့ စက်ထဲမှာပဲ run တာ (localhost) ဖြစ်လို့ အင်တာနက်ကနေ ဘယ်သူမှ မဝင်နိုင်ဘူး။

Only on your own computer. Nothing is sent to an outside server, and the server itself runs on localhost — nobody can reach it from the internet.

Project တိုင်းမှာ install ထပ်လုပ်ရလား?

Do I install it for every project?

မလုပ်ရဘူး။ စက် တစ်လုံးမှာ တစ်ခါတည်း တင်ရင် ရပြီ။ Cursor သုံးတဲ့ project တိုင်းမှာ အလိုအလျောက် အလုပ်လုပ်တယ်။ Project တစ်ခုနဲ့ တစ်ခုရဲ့ မှတ်စု မရောအောင် စနစ်က သူ့ဘာသာ ခွဲထားပေးတယ်။

No. One install per machine covers every project you open in Cursor, and the system keeps each project's notes separate automatically.

Cursor ကို update လုပ်ရင် ပျက်သွားလား?

Will a Cursor update break it?

မပျက်ဘူး။ ချိတ်ဆက်မှုတွေက Cursor ရဲ့ settings ဖိုင်တွေထဲမှာ ရေးထားတာ ဖြစ်လို့ update လုပ်လည်း မပျောက်ဘူး။ တစ်ခါတစ်ရံ ဖိုင်တွေ ပြန်စစ်/ပြန်ထည့်လို့ရတဲ့ အမိန့် ရှိတယ် — ai-memory setup --agent cursor ကို ထပ် run ရင် ပြန်ကောင်းတယ်။

No. The wiring lives in Cursor's settings files, so updates don't remove it. If anything ever looks off, just re-run ai-memory setup --agent cursor.

တခြား AI tool တွေနဲ့ရော သုံးလို့ရလား?

Can I use it with other AI tools?

ရတယ်။ နောက်ကွယ်က ai-memory က Claude Code, Codex, Gemini CLI စတဲ့ tool အများကြီးနဲ့ ချိတ်လို့ရတယ်။ ဒီ installer ကတော့ Cursor တစ်ခုတည်းကိုပဲ ချိတ်ပေးတာ — Cursor ကို အဓိက သုံးသူတွေ အတွက် ရိုးရှင်းအောင် လုပ်ထားလို့။

Yes. The ai-memory engine behind it supports Claude Code, Codex, Gemini CLI, and many more. This installer wires Cursor only — kept simple on purpose for Cursor-first users.

ဖြုတ်ချင်ရင် ဘယ်လိုလုပ်ရမလဲ?

How do I uninstall it?

Terminal မှာ ai-memory uninstall --apply ကို run ပါ။ ချိတ်ဆက်မှုတွေကို သန့်ရှင်းစွာ ဖယ်ပေးပြီး မှတ်စုတွေကို ဖျက်မလား မေးပေးတယ် — သိမ်းထားချင်ရင် သိမ်းထားလို့ရတယ်။

Run ai-memory uninstall --apply in a terminal. It cleanly removes the wiring and asks before deleting any notes — you can keep them if you want.

Dashboard ဝင်တာ username/password တောင်းနေတယ် — ဘာထည့်ရမလဲ?

The dashboard asks for a username/password — what do I enter?

Username က ကြိုက်တာ ထည့်လို့ရတယ် (ဥပမာ admin)။ Password က ကိုယ့်စက်ထဲက token ဖိုင်ထဲက စာသား — Windows ဆိုရင် PowerShell မှာ Get-Content "$env:LOCALAPPDATA\ai-memory\auth-tokens\default" နဲ့ ကြည့်ပြီး ကူးထည့်ပါ။ အသေးစိတ်ကို သုံးနည်း စာမျက်နှာက "Dashboard ဝင်နည်း" အပိုင်းမှာ ရေးထားတယ်။

The username can be anything (for example admin). The password is the text in the token file on your machine — on Windows, view it in PowerShell with Get-Content "$env:LOCALAPPDATA\ai-memory\auth-tokens\default" and paste it in. Full steps are in the "Signing in to the dashboard" section of the Usage page.

How do I know the install worked and the memory really functions?

Terminal မှာ ai-memory doctor နဲ့ စစ်ပါ၊ Cursor ထဲ Settings → MCP မှာ ai-memory server enabled ဖြစ်နေလား ကြည့်ပါ။ အသေချာဆုံး စမ်းနည်း ကတော့ chat တစ်ခုမှာ အချက်တစ်ခု မှတ်ခိုင်းပြီး chat အသစ်မှာ ပြန်မေးကြည့်တာပဲ — အသေးစိတ်ကို သုံးနည်း စာမျက်နှာက "တင်တာ အောင်မြင်လား စစ်နည်း" အပိုင်းမှာ ရေးထားတယ်။

Run ai-memory doctor in a terminal and check that the ai-memory server is enabled under Cursor's Settings → MCP. The surest test: have one chat remember a fact, then ask about it in a fresh chat. Full steps are in the "How to check it really works" section of the Usage page.
